# Portfolio site

Vite + strict TypeScript, no framework. "Departures": a board of ten places on the left, one full-bleed photograph of the current place on the right, and a hard slat cut between them; see README.md for the map. The page opens on the summit alone (the board arrives with the first step); the photographs move (WebGL, `src/living/`) and each place has a synthesised sound (`src/sound/`), behind two corner switches. On phones the photo is the whole screen and the board is a sheet.

## Commands

- `npm run dev` — dev server (no API unless `.env` sets `VITE_API_URL`)
- `npm run check` — lint + typecheck + unit tests + build. Run before every commit.
- `npm run test:e2e` — Playwright smoke suite against the real build under `/portfolio/` (rebuild first if a preview server is already running on 4173: it is reused), plus the sound check against the dev server on 5174. Locally it asks Chromium for the real GPU (`--use-angle=gl`); on a machine without one the tests that watch the photo move skip themselves.
- `npm run format` — prettier
- `npm run worlds -- <folder>` — make `public/worlds/*.webp` (landscape + upright crop per world) and `src/worlds/placeholders.json` from the source photographs, which must be in the folder under the names in the table at the top of `scripts/make-worlds.ts` (needs ffmpeg with libwebp). Run after changing a photo or a world's `focus` in `src/worlds/looks.ts`; commit the results. A unit test caps every file's size.
- `npm run video -- <file> <slug>` — compress a video into `public/videos/<slug>.mp4` (H.264, 720p, at most 2 MB). Every video goes in this way, never as a raw copy: recorders write HEVC, which Firefox can't play, and a unit test fails above 2 MB.

## Conventions

- All text lives in `src/content/` (projects, the board's places and status words, messages). Never hard-code copy in DOM code or in `index.html`: the shell has `{{slots}}` filled by `content/render.ts` at build time.
- One project = one entry in `content/projects.ts` + its place in `content/places.ts` + its look in `worlds/looks.ts` + its scene in `living/scenes.ts` + its sound in `sound/recipe.ts` + its photograph (`scripts/make-worlds.ts` maps source file to world id). Unit tests fail until all six exist. Slugs are public (links, photo and video names, API growth keys): don't rename.
- The photo is the hero. Words stand in the corner the photo leaves calm (`looks.ts`: `at`, `width`, `x`, `atTall`), with only a local shade behind them: never a scrim over the photo. After changing a look or a text, look at screenshots of that world at 1440x900, 1366x680, 390x844 and 320x568.
- Performance rules (the previous site lagged): in CSS animate only `transform` and `opacity`; no blend modes, filters, backdrop-filter or clip-path on big layers; at most three photos mounted (`worlds/photos.ts`); no scroll smoothing: travel is one step per gesture. A photo is shown only after `img.decode()`. There is one frame loop (`lib/ticker.ts`); everything that draws subscribes to it and it rests in a hidden tab, under a cover (video, sheet, raised index) and with the motion switch off. The living photo must stay GPU work: per frame the main thread sets a few uniforms and makes one draw call (budget: p95 frame under 20 ms at 1440x900 and 390x844, idle and travelling; main thread well under 1 ms a frame). Never: layered parallax, cursor-reactive effects, animated CSS filters.
- What moves in a photograph is data (`living/scenes.ts`), authored by looking at the photo with a grid over it; README "Make a place move" is the how-to. Regions stop short of solid things, moves stay small (unit tests cap them), and the canvas must stay transparent where nothing moves so the `<img>` is what you see. After changing a scene, look at two frames two seconds apart and their difference.
- Sound: off by default, never an `AudioContext` before a gesture (a browser warning in the console is a failed test), nothing downloaded: recipes in `sound/recipe.ts`, built by `sound/engine.ts` on any `BaseAudioContext`. Nobody has listened to it through the tests: the sound check only proves each place is audible, quiet (peak under 0.9), unclipped and centred.
- Words must be readable about 300 ms after a key: the cut is 300 ms (`worlds/slats.ts`), and nothing may delay the words after it lands.
- Modules that touch the DOM at import (`lib/media.ts` and whatever imports it) cannot be unit-tested in jsdom; keep logic worth testing in DOM-free modules (`content/*`, `worlds/cover.ts`, `slats.ts`, `looks.ts`, `living/raster.ts`, `noise.ts`, `scenes.ts`, `sound/recipe.ts`, `samples.ts`, `switches/prefs.ts`, `travel/gesture.ts`, `board/scramble.ts`, `nav/routing.ts`, `note/machine.ts`, `night/today-text.ts`, `lantern-math.ts`, `video/files.ts`, `lib/queries.ts`, `lib/random.ts`).
- Narrow layout = phones and upright tablets: `NARROW_QUERY`/`TALL_QUERY` in `lib/queries.ts` and the media queries in `styles/narrow.css` must agree (a unit test checks).
- No `any`, no non-null assertions, no bare `catch`: catch the specific error type and rethrow the rest. API failures are values (`ApiResult`), handled per endpoint; responses are checked with Zod.
- Never call the production API from tests or while verifying. The e2e suite fails on any request that leaves 127.0.0.1.
- CSS: one file per concern in `src/styles/`, colours and type from `tokens.css`. `narrow.css` then `motion.css` (reduced motion) must stay after the files they override.
- Accessibility is part of parity: skip link, keyboard travel (the board is one Tab stop, and reachable by Tab during the opening shot: focus entering it is a first step), focus moved to the new world's name, `aria-live` arrival line, modal dialogs for the video / Read / the note (Esc, focus return), 44 px targets, the corner switches are toggle buttons (`aria-pressed`, off = struck through, not colour alone), reduced motion = instant cuts and the motion switch starts off.
- The opening shot (`opening/opening.ts`, `styles/opening.css`): the `opening` class is set before first paint in `index.html` only when there is no `#link`. The stage changes shape exactly once, when the first cut lands, under the slats; `#cut` always has its final shape.
